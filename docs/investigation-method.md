# Metodologi Investigasi Berbasis Bukti (Adaptasi REA — `morluto/rea`)

Dokumen ini mengekstrak **metodologi investigasi dan arsitektur disiplin bukti** dari repositori resmi [morluto/rea](https://github.com/morluto/rea) (berlisensi MIT, tanpa menyalin kode) untuk diterapkan secara terstruktur pada proses porting mod **The Hordes** (`The-Hordes-1.21.1-1.6.3f.jar`, SHA-256: `4f4e308d4a412ffd9a2eee71bfb7cf729c306524ccac6b61ab4dcbca648a8574`) dari NeoForge 1.21.1 ke plugin server-only **Paper 26.3 (Java 25)**.

## 1. Arsitektur Sistem REA (`morluto/rea`)

Berdasarkan dokumentasi resmi [morluto/rea](https://github.com/morluto/rea), [AGENTS.md](https://github.com/morluto/rea/blob/main/AGENTS.md), [SKILL.md](https://github.com/morluto/rea/blob/main/.agents/skills/reverse-engineer-anything/SKILL.md), dan [MCP Contracts](https://github.com/morluto/rea/blob/main/docs/reference/mcp-contracts.md), REA bukan sekadar kumpulan dekompiler, melainkan **orkestrator investigasi lokal berbasis kontrak bukti** dengan arsitektur berlapis (dependency mengalir ke dalam):

1. **Domain Semantics & Contracts (Inti):** Mendefinisikan skema `Evidence`, `graph` (hubungan pemanggilan/modul), `limitations` (batasan cakupan analisis), dan `unknowns` (celah yang belum terverifikasi). Memisahkan secara tegas antara **Observation** (terlihat langsung pada artefak), **Derivation/Inference** (disimpulkan dari bukti), dan **Unknown** (tidak diketahui).
2. **Provider Adapters (26+ Engine):** Menjalankan backend analisis dalam subproses terisolasi — misalnya Hopper, Ghidra, IDA, Kuna (binary native), parser statis bawaan (JavaScript/Electron, .NET CIL, PyInstaller), JADX (APK Android), Binwalk/Unblob (firmware), serta Chrome DevTools Protocol & mitmproxy (web/jaringan).
3. **Shared Application Workflows:** Alur investigasi *summary-first* (mulai dari inventaris terkecil, telusuri dari entry point hingga perubahan state, simpan sesi dan bookmark agar tidak mengulang analisis identik).
4. **CLI & MCP Adapters:** Mengekspos alur yang sama melalui server MCP lokal (`npx rea-agents setup`) maupun terminal (`npx -y rea-agents@latest ...`), dengan *setup plan* read-only, backup konfigurasi otomatis, dan batas keamanan eksekusi target.

**Batasan REA untuk Mod Minecraft (JAR JVM):** Daftar target resmi [morluto/rea](https://github.com/morluto/rea) mencakup binary native, JS/Electron, .NET, APK Android, firmware, dan trafik web — **tidak menyertakan pipeline khusus mod NeoForge/Minecraft JAR** (Access Transformer + Mixin + Mojang mappings). Oleh karena itu, dalam proyek ini kita mengadopsi **metodologi investigasi dan buku besar bukti REA**, dikombinasikan dengan inspeksi statis langsung pada arsip JAR, JSON datapack bawaan, dan struktur bytecode JVM (`.class` constant pool, field, method, dan konfigurasi).

## 2. Alur Investigasi 5 Langkah (Diterapkan ke The Hordes)

1. **Rumuskan Pertanyaan Perilaku Spesifik:** Pecah mod menjadi subsistem independen: penjadwalan horde (`HordeEvent`, `HordeSavedData`), tabel spawn & skrip (`HordeTableLoader`, `HordeScriptLoader`), infeksi & penyembuhan (`InfectionEventHandler`, `InfectedEffect`, `InfectionData`), entitas zombie player (`ZombiePlayer`, `DrownedPlayer`, `HuskPlayer`), perintah (`/hordes`), perilaku misc (`MiscEventHandler` + 26 mixin), serta komponen client-only (`client/*`).
2. **Kumpulkan Bukti Multi-Lapisan Secara Statis:**
   - **Metadata & Manifest:** `META-INF/neoforge.mods.toml`, `META-INF/accesstransformer.cfg`, `hordes.mixin.json`, `config_defaults/hordes-info.json`.
   - **Data & Konfigurasi Bawaan:** Seluruh JSON di `config_defaults/data/hordes/**` (tabel spawn, skrip kondisi, daftar entitas penginfeksi, 11 konversi infeksi, 30 proteksi wearable, item penyembuh & imunitas, biome husk) dan `config_defaults/assets/hordes/**` (atribut, terjemahan, suara).
   - **Bytecode Kelas (178 `.class`):** Ekstraksi nama kelas, field, tanda tangan method, string kunci konfigurasi, serta konstanta numerik dari constant pool.
3. **Catat Temuan dengan Label Epistemik & Batasan:** Setiap keputusan porting di `docs/parity-matrix.md` wajib mencantumkan:
   - **Evidence ID** (`EV-01` s.d. `EV-14`) yang merujuk tepat ke file/kelas di dalam JAR atau Javadoc [Paper 26.3](https://jd.papermc.io/paper/26.3/).
   - **Status Epistemik:** `Terverifikasi` (terlihat langsung di JAR/Javadoc), `Disimpulkan` (diturunkan dari struktur field/method), atau `Tidak diketahui` (memerlukan verifikasi runtime pada server Paper 26.3).
   - **Batasan (Limitations):** Misalnya, analisis statis tidak mengamati eksekusi runtime; mixin client (`MixinLevelRenderer`, `MixinLivingEntityRenderer`, `MixinVillagerProfessionLayer`) mustahil direplikasi di server-only plugin.
4. **Dilarang Menebak API atau Mengisi Celah:** Setiap kelas dan method Paper 26.3 (`paper-plugin.yml` `api-version: '26.3'`, `LifecycleEvents.COMMANDS`, `ArgumentTypes.players()`, `Mannequin`, `Attribute`, `PersistentDataContainer`) diverifikasi langsung dari [PaperMC Docs](https://docs.papermc.io/paper/dev/getting-started/paper-plugins/) dan [Paper 26.3 Javadocs](https://jd.papermc.io/paper/26.3/).
5. **Verifikasi Sebelum Klaim Selesai:** Pada Mode B (sandbox offline tanpa JDK 25 & jaringan), kode diverifikasi secara statis dan dilengkapi `neon-testkit` + skrip uji agar pengguna dapat menjalankan gerbang `AT-01` s.d. `AT-09` pada server Paper 26.3 lokal.
